### SRC-01 evidence (2026-09-09)

**Files:** `packages/plugins/plugin-harness-research/` (new plugin:
`plugin.json`, `src/index.ts`, `test/research-harness.test.ts`,
`package.json`; deps: kernel, contracts, storage, fake-providers).

**Design:** a `harness` plugin that orchestrates the zero-LLM pipeline and
performs no raw I/O itself. Injected deps: `search` (SearchProvider —
terms-gated adapters are SRC-02; tests use FakeSearchProvider), `fetchPage`
(host-bound safeFetch path with SSRF/size/time/MIME guards),
`repositories` (owner-scoped storage), optional `budget` (BudgetService).
Per hit: contracts default-deny check (linkedin.com et al.) BEFORE any
fetch; budget cap (`maxFetches`) stops the loop; failures are recorded and
the pipeline continues. Each success stores the document (sha256 content
hash, fetchedAt, provider-declared publishedAt/origin, raw MIME/text) and
paragraph excerpts (≤ 20/doc, ≤ 8192 chars) — provenance stored before any
merge (ADR 0003). Budget: reserve (searchCalls 1, fetches maxFetches,
nominal 1-token ceilings — zero model calls by construction) before the
search; settle with actual fetches in a `finally`. Kernel round-trip
covered.

**Commands:** `npx vitest run packages/plugins/plugin-harness-research` →
8/8 pass (provenance round-trip incl. owner-scoped passages; deny-list
never fetched; continue-past-failures; budget reservation/settlement rows
in usage_ledger with actual fetch counts; run-before-activate refused;
extractPassages caps; kernel round-trip). `npm run check` → PASS all 7
steps.

**Security note (add-plugin acceptance):** what it can touch — evidence
rows for the calling owner only (owner-scoped repositories), pages
reachable through the host's safeFetch path, and one budget reservation.
What denies it: contracts default-deny list (per-fetch, before I/O),
safe-fetch guards in the host wiring, budget caps (daily, per-owner),
kernel manifest validation (INV-003: no paid/computer capabilities), and
the plugin-import policy scan (no raw fs/net in plugin source). Known open
point: dynamic research fetches cannot be enumerated in the manifest
network allowlist — governance for fetch targets is the safe-fetch guards
plus the deny list until CORE-08's site-access policy plugin adds the
robots/ToS registry; revisit then.

**Risks / open questions:** naive paragraph extractor (replaced by SRC-03
readability); canonical_url mirrors original_url until dedup/canonicalization
lands; per-hit fetches are sequential (bounded by maxFetches).

**Next suggested task:** SRC-02 (fixtures-backed search adapter behind a
terms gate — the FakeSearchProvider already fits) or SRC-03 (readability
extractor).

Exit: useful searchable evidence with stored provenance; zero synthesis calls.
